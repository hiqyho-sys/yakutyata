# Проверка безопасности и готовности к передаче

Дата: 05.10.2026. Область проверки: текущий статический сайт «Якутята», каталог и клиентская логика. Это анализ исходников и пользовательских сценариев, а не тест доступа к чужим системам, аккаунтам или банковским счетам.

## Результат проверки кода

Критические и высокие уязвимости в проверенном исходном коде не обнаружены. Посетитель не может изменять каталог или реквизиты через сайт. В проекте нет авторизации, базы данных, загрузки пользовательских файлов, форм отправки, внешних JS/CSS-библиотек, аналитики или серверных API. Нет `eval`, обработчиков событий в HTML и обращений к сторонним сетевым сервисам из скрипта.

Все внешние активные ссылки ведут в предоставленную группу `https://vk.ru/yakutiata`; новые вкладки используют `noopener noreferrer`. Телефонные ссылки согласованы. Четыре кнопки копируют те же номера, которые показаны посетителю. Реквизиты публичные, предоставлены владельцем проекта; принадлежность счетов технический аудит не подтверждает.

## Исправления

1. Закрыт условный риск при будущем импорте каталога: пути изображений проверяются по строгому формату локального WebP, а HTML-атрибуты экранируются. В текущем каталоге вредоносных путей не было.
2. Добавлена Content Security Policy: единственный скрипт разрешён по SHA-256; внешние скрипты, сетевые соединения скрипта, объекты, фреймы и отправка форм запрещены. Изображения разрешены с текущего сайта и встроенные `data:`. Inline-стили сохранены для существующей графики и анимаций. `Referrer-Policy` задана через meta `no-referrer`.
3. Исправлено повторное копирование: исходная надпись кнопки сохраняется один раз, прежний таймер отменяется. Два быстрых клика больше не оставляют постоянное «Скопировано».
4. Невидимый буфер фотографии истории исключён из чтения экранным диктором.
5. Добавлен каталог в JSON и проверяемая сборка: синхронизируются данные, карточки, счётчики и фотографии истории; JSON при встраивании в скрипт экранирует `<`, чтобы текст анкеты не мог закрыть тег script. Инструмент пересчитывает CSP после изменений.

## Проверки перед выпуском

В отдельном проходе проверены 44 записи и соответствующие карточки: уникальные ID, категории, имена, возраст и поисковые псевдонимы. Все 184 фотографии альбомов и 42 превью присутствуют; WebP-файлы декодируются. Все девять собак в истории используют фотографии из собственных анкет. У двух кратких упоминаний отсутствующие фото не заменены чужими.

Проверены поиск по имени, нормализация «е/ё», псевдонимы, пустая выдача и последовательность 12 → 24 → 36 → 44 карточки. Проверены банковские подписи, телефон, внешние ссылки и внутренние якоря; повторяющихся HTML ID и битых якорей не найдено.

Автоматические проверки и браузерный проход финальной опубликованной версии описаны в итоговом разделе ниже. Проверки не удостоверяют актуальность статусов собак: до официальной публикации редактор команды сверяет каталог от 22.09.2026 и статистику от 03.10.2026.

## Границы защиты и доступа

CSP — дополнительный барьер при внедрении чужого кода; она не защищает от владельца доступа, который одновременно изменит страницу и саму политику. Возможности заголовков, инфраструктура GitHub Pages, права владельца, двухфакторная аутентификация и банковские счета не изменялись и не проходили независимый аудит.

Запрет встраивания сайта в чужие iframe (`frame-ancestors`) работает только в HTTP-заголовке, а не в meta. В архиве нет заявления, что GitHub Pages получил этот заголовок. На другом хостинге его следует настроить отдельно по HANDOVER.md.

Сайт не предотвращает появление фишинговой копии на другом домене. Для посетителей важна официальная HTTPS-ссылка из группы команды, для редакторов — защита GitHub-аккаунта и независимая сверка любых изменений реквизитов. Вход в банк, пароль и SMS-коды сайт не запрашивает.
