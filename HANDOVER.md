# Передача и публикация сайта «Якутята»

Версия подготовки: 5 октября 2026 года.

## Что передать команде

Передайте весь архив, а не один HTML: `index.html`, папку `catalog/`, `.nojekyll`, `data/`, `tools/` и инструкции. Сайт статический: сервер приложения, база данных, платные API и ключи не нужны. Фотографии Анны и первого экрана встроены в HTML; фотографии каталога лежат рядом в `catalog/`.

Работающая публикация: https://hiqyho-sys.github.io/yakutyata/

Исходники: https://github.com/hiqyho-sys/yakutyata

## Опубликовать на GitHub Pages

1. Создайте репозиторий в аккаунте команды. Для бесплатного GitHub Pages используйте публичный репозиторий. Учтите: HTML, фотографии и исходные анкеты станут публичными. В архиве нет приватных ключей и учётных данных.
2. Распакуйте архив. Загрузите его содержимое в корень репозитория, чтобы `index.html` находился сразу в корне. Не загружайте ZIP вместо распакованных файлов. Сохраните структуру папок и `.nojekyll`.
3. Откройте **Settings → Pages → Build and deployment**. Выберите **Deploy from a branch**, ветку **main** и папку **/(root)**; нажмите **Save**.
4. Дождитесь успешного задания **pages build and deployment** в **Actions**. Откройте ссылку из **Settings → Pages**. Используйте HTTPS; для собственного домена включите **Enforce HTTPS**, когда сертификат станет доступен.
5. Пройдите сценарии ниже. При переносе на другой статический хостинг публикуйте `index.html` и `catalog/` с теми же относительными путями. Документы и инструменты сборки можно хранить только в репозитории, не публикуя их на другом хостинге.

Существующий репозиторий принадлежит текущему владельцу. Сам архив не передаёт права на аккаунт. Команде следует использовать собственный аккаунт либо согласовать передачу репозитория с владельцем через GitHub. Пароли и персональные токены передавать друг другу не нужно.

## Обновлять собак

Установите Python 3.10 или новее с официального сайта python.org. Дополнительные пакеты не нужны. Откройте терминал в распакованной папке проекта.

1. Сделайте резервную копию или отдельную ветку Git.
2. Измените `data/dogs.json`: текст, имя, возраст **на дату анкеты**, дату публикации и фотографии нужной собаки. Сохраните существующий `id`; новые ID должны быть уникальными. Не используйте HTML в текстах.
3. Сохраните новые фото в WebP в `catalog/`. Допустимые имена: латинские буквы, цифры, дефис и подчёркивание; пример `catalog/new-dog-01.webp`. Внешние URL, SVG, `../` и ссылки `javascript:` не допускаются. Для превью можно положить отдельный WebP и указать его путь в поле `thumbnail` анкеты. При `thumbnail: null` будет использовано первое фото; при отсутствии фото оставьте `images: []`, `thumbnail: null` и `photo_type: "none"`.
4. Главы истории используют отдельные ссылки на записи каталога: `data/story.json`. При удалении собаки замените её там другой реальной собакой. Не подменяйте имя чужой фотографией.
5. Выполните `python tools/catalog.py --build`. Инструмент обновит встроенные данные, карточки, числа и историю; пересчитает защитную политику для скрипта.
6. Выполните `python tools/catalog.py --check` и `python -m unittest discover -s tools -p 'test_*.py'`. Если установлен Node.js, дополнительно выполните `node tools/test_runtime.mjs`.
7. Проверьте изменённые карточки в браузере и сохраните все изменённые файлы в `main`. GitHub Pages автоматически опубликует обновление. Не публикуйте вариант, если проверка сообщает об ошибке.

Не меняйте встроенный массив `DOGS` отдельно от карточек. После любых ручных изменений JavaScript в `index.html` обязательно выполните `--build`: без нового хеша браузер заблокирует изменённый скрипт. Не удаляйте CSP ради устранения такой ошибки.

Основные поля записи в `dogs.json`: `name` — имя, `aliases` — другие варианты имени, `sex` — пол, `age` — возраст из анкеты, `category` — `puppy`, `teen`, `adult` или `unknown`, `special_care` — нужна ли особая забота, `about` — характер, `health` — здоровье, `features` — важные особенности, `date` / `edited_at` — даты публикации и редактирования, `source_text` — полный исходный текст. `partial: true` требует пояснения `info_notice`. Служебные сведения о происхождении анкеты сохраняйте; возраст и медицинские данные меняйте по подтверждённой новой анкете, а не автоматически по календарю. Для новой записи удобнее скопировать структуру существующей и заменить её собственными сведениями и новым ID.

Поле `exported_at` — дата актуальной выгрузки, а не дата сборки сайта. Не меняйте его на сегодняшнее число, если сведения не обновлялись.

## Сверить содержание перед официальным запуском

Каталог основан на выгрузке от **22.09.2026**: 44 записи, 42 с фото и 2 кратких упоминания без фотографий. Это не подтверждение, что все собаки сейчас ищут дом. Анна должна сверить доступность, возраст, состояние здоровья и актуальные фото. Не заменяйте неизвестные сведения предположениями.

Статистика **867 спасённых жизней** и **164 собаки за 2026 год** предоставлена командой **03.10.2026**. Числа на главной странице не связаны с количеством анкет: это разные показатели. При обновлении статистики измените обе копии общего числа: первый экран и блок результатов.

Телефон, группу ВК, получателя и четыре банковских реквизита нужно подтвердить у Анны по ранее известному контакту. Проверка кода подтвердила совпадение отображаемого номера и текста кнопки копирования, но не принадлежность банковского счёта.

Команда также подтверждает разрешение на использование переданных фотографий и текстов. Веб-сайт не запрашивает пароль, SMS-код, данные входа в банк или полные платёжные данные посетителя. Перевод выполняется в приложении банка самого посетителя.

## Сценарии после каждой публикации

- Открыть главную страницу: сияние и эффекты работают сразу. Отключить анимации, включить обратно; после перезагрузки они снова включены.
- Пройти три главы истории; фотографии и подписи относятся к одной собаке. Выбрать города на глобусе.
- Найти собаку по имени, проверить «е/ё», категории, пустую выдачу и «Показать ещё».
- Открыть полную и краткую анкеты. Перелистнуть альбом кнопками и стрелками клавиатуры. Закрыть Escape; фокус должен вернуться на кнопку карточки.
- Дважды быстро нажать копирование реквизитов: подпись возвращается к исходной. При запрете буфера доступно ручное копирование. Сверить номер и назначение перевода.
- Проверить телефон и адрес ВК, все фото, узкий экран телефона и отсутствие ошибок в консоли браузера.

## Доступ и защита публикации

Включите двухфакторную аутентификацию GitHub и сохраните коды восстановления отдельно. Давайте доступ только участникам, которым нужно обновлять сайт; проверяйте изменения реквизитов и ссылок перед публикацией. На GitHub Pages публикация из ветки сама по себе не ждёт успешного локального `--check` — запускайте проверку до сохранения изменений в `main`.

Размещайте одну официальную ссылку в группе ВК и сообщите её аудитории. Защитная политика сайта не может запретить злоумышленнику создать копию на другом домене или предотвратить подмену файлов при захвате аккаунта владельца. Поэтому защита аккаунта и проверка официального адреса важны не меньше кода.

Для хостинга, на котором доступны HTTP-заголовки, дополнительно настройте `Content-Security-Policy: frame-ancestors 'none'`, `X-Content-Type-Options: nosniff` и `Permissions-Policy: camera=(), microphone=(), geolocation=()`. Дополнительная CSP в заголовке применяется вместе с HTML-политикой. Не помещайте `frame-ancestors` в meta: браузеры там её не применяют. Этот архив не устанавливает HTTP-заголовки GitHub Pages.

## Если обновление неудачно

Откатите последний изменяющий коммит в GitHub либо восстановите предыдущую проверенную копию `index.html`, `data/` и затронутых фото. Дождитесь повторной публикации в Actions и заново проверьте страницу. Не удаляйте весь репозиторий для отката. Коды входа, токены и ключи никогда не помещайте в публичные файлы, историю Git или архив.
